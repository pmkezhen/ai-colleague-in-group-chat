# 分身进入新业务域时先跑影子模式，不直接开口

分身在一个新业务域（当前是公司的中台项目）具备排查能力之后，**不立即在群里输出结论**。每次实施求助照常触发完整排查，但产物只写入本地诊断记录，群里一个字都不发。等到诊断准确率经过对照打分并达标，才允许出声。

这么做是因为新域缺的不是能力而是**证据**。中台的因果知识在本仓库为零：十余条排查记忆全是另一个业务域的，skill 也全是那个域的。让一个没有该域知识的 agent 直接对着公司主力项目群开口，输出的是**有说服力的噪声**——而它比「我不知道」危险得多，因为实施会照着做。

## 为什么打分不需要一个权威的人

新域没有人能为分身的结论签字：人格主号不参与中台，中台侧也给不出一个固定的权威回答人。影子模式绕开了这个死结——对照物不是某个人的判断，而是**那件事最后实际是怎么被处理的**：工单系统里工作项的状态流转（转开发 /转产品 / 已完成）、实际执行的处置。那是事实，不需要谁背书。

## 它同时解决了语料问题

中台的实施需求只有 270 条，而且**没有任何一条记录了「查了什么、看到什么、所以判断是什么」**——工单只有症状和最终状态，中间那段从不留痕。**要蒸馏的排查过程从未被记录下来，因此不能靠收集得到，只能靠制造。**影子模式每处理一次求助就产生一条完整轨迹（症状 → 查询 → 观察 → 根因假设 → 建议处置），这正是工单和群聊里都缺的那一段。

## 边界

- 影子期需要读取消息和理解截图，但不外发。现有的群聊回复控制把「理解」和「开口」绑成一个开关（媒体理解受 `group_reply_enabled` 约束），影子模式要求把两者拆开。
- 影子诊断只写本地，不进群记忆、不进对话上下文，也不构成排查任务的结论。潜伏期公开消息本身不是影子诊断；后来开口时，它们可以在最近两小时窗口内作为近期对话上下文，使分身承接自己一直观察的群聊。媒体解析正文、影子诊断和潜伏期旧表达仍不因此注入、重新路由或补发。
- 冷启动仍需人：影子模式不能从零起步，新域的第一批排查记忆和 skill 由人格主号亲自带编码 agent 跑真实问题产出。另一个业务域的十余条记忆就是这么来的，不是分身自己长出来的。
