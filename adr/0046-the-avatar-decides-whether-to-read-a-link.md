# 链接读不读由分身号判断，不由词表判断

2026-08-27 15:23，群里连着两条消息读同一份钉钉文档，落在两条互相打架的分支上：

| 时刻 | 成员说的 | 措辞门 | 封口结论 | 群里听到 |
|---|---|---|---|---|
| 07:23:31 | `@分身 解析并读取这个钉钉文档` | 放行 | `failed_closed` | 你发的材料我没能读取 |
| 07:25:01 | `这个钉钉文档地址 https://alidocs...` | **拒绝** | **`ready`，零材料** | 这个钉钉文档链接我还是读不到内容 |

第二轮的材料清单是空的。分身号手上没有那个链接，也不知道自己本来读得了它，「读不到内容」这句话是它猜出来的——它连试都没试过。这正是图片和附件那一侧修过的病（ADR-0031，未收录：手边读不到的材料不许静默丢掉），在链接这一侧原样复发。

而第一条的失败与措辞无关：引用把链接正确带进了材料清单（`association_basis: "quote"`），门也放行了，最后挂在 MCP 传输层。同一份文档在同一台机器上，冒烟测试读得到 28,676 字。

## 事实：门从来没有挡住过一次危险读取

措辞门是为一件真事建的。建门那次提交写着「明确读取不能靠孤立关键词猜测，否则普通故障讨论也会产生外部副作用」——怕的是群里讨论故障时，分身自作主张去访问消息里那个地址。库里这类消息确实存在：群里贴过测试环境的内网登录页地址，还有带内网 IP 的第三方系统链接，共 7 条。

**但这 7 条危险链接一条都没走到门跟前。** 它们全部没有被受理为目标消息——不是跟分身号说的话，准入那一关就结束了。

反过来，门也拦不住它声称要防的东西。带上动作词，同一个内网地址照样放行：

```
@分身 读取这个链接 http://<内网地址>/login   → 放行
@分身 帮我看看这个网页 http://<内网地址>/     → 放行
```

原因是它判断的东西和它要防的东西没有关系：门问「这句话里有没有动词」，风险问「这个地址该不该访问」。

## 事实：它挡下的九次，九次都是错的

回放全部含链接的入站消息：35 条里 19 条被受理为目标消息，门放行 10 条、拦下 9 条。这 9 条是：

```
① https://alidocs.../pGBa2Lm8...                    裸链接
② https://redis.io/iris/                            裸链接
③ https://alidocs.../pGBa2Lm8... ⏎ 解析这个钉钉文档
④ ...the-ai-native-sdlc-playbook ⏎ 这个内容主旨 @分身
⑤ ...how-anthropic-secures... ⏎ 读取这个内容
⑥ ...how-warp... ⏎ @分身 这个内容进行总结
⑦ ...claude-in-chrome... ⏎ 这个链接再试试读取
⑧ 刚才图片没截全…你先读取并解析文档内容…@分身
⑨ 这个钉钉文档地址 https://alidocs.../0eMK...
```

人格主号确认这些都该读。九次拦截，九次错，零次拦对——目标全是 `alidocs`、`claude.com`、`redis.io`、`devops.aliyun.com`，公开的或分身号有权限的文档。

被拒的理由都是措辞的形状，不是意图的差别。⑦「这个链接再试试读取」句子里「链接」和「读取」两个词都在，被拒是因为「读取」落在句尾、后面没有词可供前瞻；同一个词挪到句首就放行。⑤「读取这个内容」过了动作那一关，倒在「内容」不在链接指称词表里（表里有「文档内容」，没有「内容」）。

同一份文档要发三次才读得到：`https://redis.io/iris/` 裸链接（未读）→ `@分身 再看看这个地址下的内容`（读了）。钉钉那份更长：裸链接（未读）→ `解析这个钉钉文档`（未读）→ `@分身 请读取这个钉钉文档`（才读）。

## 事实：词表补不完，因为分辨依据不在词里

每漏一次就往词表里加一个词，上一次加的是「文档内容」。但词的分布不支持这条路——群里「看下」出现 88 次，跟链接有关的只有 1 次：

```
@同事A @同事B 帮忙看下，某仓
@同事C @同事D @同事E 麻烦看下          ← 「麻烦+看下」正则直接命中
你看下正文
```

放严就漏读，放宽就误读。而「打开看下」和「你看下正文」字面上分不开，分得开的是别的东西：谁在跟谁说话、上一条是不是链接、十分钟内有没有唯一候选。这三件事系统全都记着，但函数签名是 `explicitly_requests_link_read(text, admission_basis)`——它只拿得到当前这条消息的字符串，看不见上一条是什么。要它做的判断，输入有一半没传给它，再加多少词都补不上。

门声称承担的第三项——否定表达「别读这个」——在全部历史消息里出现 **0 次**。

第二项要留下。门里有一条「这句话点名了别人」的判断，它不是措辞判断，是「这句话说给谁」的判断。历史那 7 条之所以没到门口，是因为当时没有开着的闲聊窗口；准入只在结构化点名那条通道上核对点名对象，闲聊窗口按发言人放行，发现不了成员转头对别人说话。所以撤门时这一条必须单独接住，不能跟着一起消失。

## 决策

**撤掉措辞门。** 一条消息被受理为目标消息、其中的链接进了完整表达，就是可读材料，不再用句子的措辞二次判定。

读取照旧在封口时发生，正文随材料一起进模型输入——不改成「先问分身号要不要读」。多一轮模型往返在群聊里是成员感受得到的等待，而省下的那次调用没有人感受得到；19 条被受理的含链接消息里，没有一条是「给了链接却不希望它看」。

**两条否决留下。** 一是成员明确说「不要读」「只是分享，不要读取」，就不读，也不催他重发。二是这句话点名了别人而不是分身号——闲聊窗口里成员转头对同事说「@同事C 帮忙看下 http://…」，链接不归分身号读。这不是被撤掉的那道门的残余：那道门要求成员先说出动词，把没说当成不同意；这里只认说出口的否定，默认放行、否定否决，方向相反。它在历史消息里一次也没出现过——这说明它不足以成为门存在的理由，不说明成员说了以后可以不听。

三道判断因此各归其位，每道只回答一件事：

- **准入**：这条消息是不是在跟分身号说话。（挡住了全部 7 条危险链接；闲聊窗口通道看不出句子点的是谁，由上面那条否决补齐）
- **地址边界**：这个地址能不能访问。（`is_global` 挡住 RFC1918 与本机代理的 fake-ip 段）
- **分身号自己**：读回来的东西用不用得上。它看得见两小时上下文，措辞门看不见。

这与 ADR-0009 是同一条原则的同一次应用：「用规则和阈值复刻这项能力等于在一个会思考的部件之外再造一个更弱的判断层」，以及「安全边界必须移到工具调用那一刻而不是留在模型内部」。地址边界就在工具调用那一刻，词表在模型之前。

## 边界

**不变的**：五条上限、可读类型白名单、链接读取总开关、`is_global` 地址边界、链接正文是资料不是指令、读不到就明确失败关闭，以及上面那两条否决。撤的只是「这句话的措辞像不像请求」这一层。

**够不着仍然要求重发**，但信号换了：光提到「链接」「网页」不算——「我们的 URL 规范是什么」也命中这些词，拿它当数等于把撤掉的词表从「读不读」搬到「答不答」上。现在要么这句话自带地址却没成为材料，要么回看范围里确实躺着一个够不着的链接，才请成员引用或重发。

**读取路径**：钉钉文档走自己的 MCP 网关（1.2 秒，不占额度）；公开网页本机优先。本地已通过 URL、DNS 和 IP 安全边界的当前跳，在正文为空（`LINK_BODY_MISSING`，典型是 JS 渲染页）、读取超时或连接失败时可以用 Firecrawl 兜底。`LINK_TARGET_BLOCKED` 仍然绝对不兜底：被 `is_global` 拒绝的地址交给外部网络出口，等于绕过自己的安全边界。

**代价**：闲聊窗口里贴的无关链接会被读一次，读回来的内容进上下文，可能让回答跑偏。接受这个代价，因为反方向的代价已经在真实数据里发生了九次，而这个方向一次都没发生过。真出现时，正确的补法是收紧准入或地址边界，不是把词表请回来。

**未解**：有些内网把公网号段当私网用，这类地址 `is_global` 返回真，地址边界放行。这是独立的缺口，与本决策无关，也不因撤门而变大——措辞门本来就放行带动作词的内网地址。单独修。

## 同时修正的既有记录

领域词表里「链接材料」原文写「只有当前完整表达明确要求阅读该链接时才读取」。「明确要求」被实现成了措辞匹配，正是本决策要撤的东西。改为按材料是否进入完整表达判定，术语表不再暗示存在一道措辞门。

ADR-0031 立的规矩是「读得到却没被选中的材料不进模型输入——那是他没指这一份，不是他该知道的坏消息」。那条规矩的前提是「没被选中」这个判断可靠；在链接这一侧它不可靠（九次全错），所以本决策不是给它加例外，而是移除那个不可靠的判断，让链接回到「进了完整表达就是材料」的正常轨道。
