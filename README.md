# 一个 AI 分身在真实工作群里的设计决策

2026 年 8 月起，我把一个闲置微信号做成了自己的 AI 数字分身，放进公司的几个
工作群：回答业务问题、陪同事闲聊、读截图和文档，后来也帮忙查生产问题、准备修数
方案。它在群里公开自己是 AI，不替我拍板。

两个月里，每一次它在群里出丑、答非所问或者该闭嘴时没闭嘴，我都写一篇架构决策
记录（ADR）：当时发生了什么、查到什么事实、决定怎么改、否掉了哪些方案。这里是其中
12 篇。

## 读法

- **编号沿用原始编号**，中间的空号是没有收录的篇目（已作废、纯本机运维，或者
  绑死在公司系统上）。正文引用到未收录的篇目时，会顺带用一句话说明它讲什么。
- **日期、数字、群聊原话都是真实的**。人名、群名、公司系统名、单号已经替换或删掉。
- 正文里的 `函数名`、`表名` 来自实现代码，代码目前没有公开。不影响读懂决策本身。

## 几个词

| 词 | 意思 |
|---|---|
| 人格主号 | 我本人的微信号。分身是「我的」分身 |
| 分身 / 分身号 | 那个 AI 微信号 |
| 完整表达 | 一个人一口气说完的一件事：可能是好几条文字，加上图片、附件、链接 |
| 封口 | 判定这次表达已经说完，材料集合固定下来 |
| 材料 | 随话一起来的图片、附件、公众号文章、链接、转发的聊天记录 |
| 闲聊窗 | 分身回过某人之后十分钟内，这个人不用 `@` 也能接着跟它说 |
| 说话 / 潜伏 | 群的两种状态：说话群它会开口；潜伏群它只看不说 |
| 准入 | 一条消息算不算「在跟分身说话」；另一层是这个群能不能用生产资源 |
